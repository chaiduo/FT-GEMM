01 / THE PROBLEM

为什么要把容错做进 GEMM？

FP8 提高吞吐并降低带宽压力，但更低精度与更大规模计算也提高了数值错误被放大的风险。 FT-GEMM 让每个输出 Tile 同时拥有行、列校验和：一个异常行与一个异常列的交点，即为可纠正元素。

优化过程中，计算从标量 CUDA Core 迁移到 WGMMA，数据搬运从同步拷贝迁移到 TMA， 校验数据则从在线重算逐步迁移到可复用缓存。每一阶段都保留相同的 FP8 输入、FP32 累加与 Tile-local ABFT 语义，确保性能提升不是以移除容错能力为代价。

INPUTFP8 E4M3

A、B 使用低精度存储；所有阶段采用统一矩阵布局与输入口径。

COMPUTEFP32 accumulate

WGMMA 在 Tensor Core 上执行乘加，累加器与输出 C 保持 FP32。

RESILIENCETile-local ABFT

每个 64×64 子块独立检测、定位并纠正单点输出错误。

03 / ABFT INVARIANT

性能路径改变，校验语义不变

实际校验和从输出 C 归约，期望校验和由输入 A/B 推导。幅值加权阈值吸收 FP8 与累加顺序造成的数值噪声。

行残差定位异常输出行，列残差定位异常输出列；两者交点给出候选错误元素。 只有同时满足行列一致性与阈值条件时才执行纠正，避免将正常舍入误差当成故障。 

C[r,c] = Σₖ A[r,k] × B[c,k]

  > abs_tol + rel_tol × max(1, scale)

  0.5 × (row_delta + col_delta)

S0

Correctness baseline

Native Tiled ABFT

3.847 TFLOPS

先做正确，再谈性能

16×16 CUDA Tile 将 A/B 搬入 shared memory 后执行标量 FMA。GEMM 与 ABFT 分成两个 kernel，期望 checksum 对每个输出 Tile 重新扫描输入，因此校验成为主耗时。

  • 机制每个线程负责一个 C 元素，K 维按 16 分段加载，阶段之间使用 __syncthreads()。
  • 收益建立清晰的数值基线和故障注入接口，便于后续版本逐项验证。
  • 剩余瓶颈标量 FMA 未使用 Tensor Core，ABFT 额外读取 A、B、C，校验耗时仍占主要比例。
瓶颈：重复 A/B 扫描稳态：35.726 ms

S1

Tensor Core data path

TMA-WGMMA ABFT

128.738 TFLOPS

把数据搬运和矩阵计算异步化

TMA 双缓冲预取下一 K Tile，WGMMA 消费当前 Tile；expected checksum 在 GEMM 前准备，actual checksum、检测和纠错融合在输出路径。

  • 机制两个 shared-memory stage 由 full/empty mbarrier 交替保护，phase 每绕过环形缓冲一次翻转。
  • 收益TMA(k+1) 与 WGMMA(k) 重叠，并把 FP8 矩阵乘法迁移到 Hopper Tensor Core。
  • 剩余瓶颈完整 expected checksum 仍需在每次输入变化时准备，主 CTA 仍采用 64x64 Tile。
阶段提升：33.5×TMA + WGMMA

S2

Move work off hot path

Full Expected-checksum Cache

132.524 TFLOPS

将完整期望值移出 K-loop

Metadata kernel 为每条 checksum 分配一个 warp，32 个 lane 并行 K 维归约。主 kernel 只保留 actual reduction、阈值判断、纠正和写回。

  • 机制每个 lane 以步长 32 遍历 K，随后通过 __shfl_down_sync 完成 warp 内归约。
  • 收益完整 expected row/column checksum 在冷路径生成，稳态主 kernel 不再读取 A/B metadata。
  • 剩余瓶颈64×64 CTA 工作量偏小，TMA、WGMMA 与校验仍由同一 warpgroup 交错承担。
阶段提升：3.34×First call：3.015 ms

S3

Warp specialization

Wide 128×128 Mainloop

232.608 TFLOPS

让搬运、计算和校验各司其职

CTA 扩展为 128×128×32：一个 32 线程 producer warp 管 TMA，两个 128 线程 consumer warpgroups 管 WGMMA；输出阶段由 consumer threads 覆盖四个 64×64 ABFT 子块。

  • 机制producer 只推进三阶段 TMA 环形缓冲，consumer 在独立 warpgroup 中等待 full barrier 后发射 WGMMA。
  • 收益扩大 CTA 提高每次 TMA 的计算复用，并减少 64×64 Tile 的调度开销。
  • 平衡点90 registers/thread 与 shared-memory 占用仍允许 2 CTAs/SM，保持足够并发。

S4

K128 + cluster multicast

跨 CTA 复用 A Tile

256.520 TFLOPS

摊薄同步成本，复用 global traffic

每个 TMA stage 扩展到 K128，一次同步连续发射四个 K32 WGMMA。2×1 CTA cluster multicast A，B 由两个 CTA 分别加载。

  • 机制cluster rank 0 发起 A Tile multicast，mask 0x3 同时投递到两个 CTA；每个 CTA 独立加载自己的 B Tile。
  • 收益A 的 global-memory 流量在两个 N 邻接 CTA 间复用，K128 将 barrier 成本摊到四次 WGMMA。
  • 占用率恢复A/B mainloop storage 与 C epilogue storage 按生命周期复用，将 shared memory 控制在 100,608 B。
