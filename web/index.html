01 / THE PROBLEM

为什么要把容错做进 GEMM？

FP8 提高吞吐并降低带宽压力，但更低精度与更大规模计算也提高了数值错误被放大的风险。 FT-GEMM 让每个输出 Tile 同时拥有行、列校验和：一个异常行与一个异常列的交点，即为可纠正元素。

INPUTFP8 E4M3

A、B 使用低精度存储。

COMPUTEFP32 accumulate

WGMMA 累加与 C 输出保持 FP32。

RESILIENCETile-local ABFT

检测、定位并纠正单点输出错误。

03 / ABFT INVARIANT

性能路径改变，校验语义不变

实际校验和从输出 C 归约，期望校验和由输入 A/B 推导。幅值加权阈值吸收 FP8 与累加顺序造成的数值噪声。

C[r,c] = Σₖ A[r,k] × B[c,k]

|expected - actual|
  > abs_tol + rel_tol × max(1, scale)

C[bad_row,bad_col] +=
  0.5 × (row_delta + col_delta)

S0

Correctness baseline

Native Tiled ABFT

先做正确，再谈性能

16×16 CUDA Tile 将 A/B 搬入 shared memory 后执行标量 FMA。GEMM 与 ABFT 分成两个 kernel，期望 checksum 对每个输出 Tile 重新扫描输入，因此校验成为主耗时。

Overlap independent work

Batched Multi-stream Pipeline

0.2527 TFLOPS

用批次间并发隐藏校验耗时

输出 Tile 被切成批次，GEMM、Checksum 与 Detect/Correct 分配到三条非阻塞 Stream，并由 CUDA Event 维护依赖。

S3

Fully online fusion

TMA-WGMMA Fused ABFT

33.21 TFLOPS

输入只进入 CTA 一次

TMA 双缓冲预取下一 K Tile，WGMMA 消费当前 Tile；期望 checksum 与 mainloop 同时生成，实际 checksum、检测和纠错融合在唯一一次 C 写回之前。

阶段提升：8.52×A/B 每次变化仍公平

// TMA(k+1) overlaps WGMMA(k)
cute::copy(tma_a.with(storage.full_barrier[write_stage]),

S5

Move work off hot path

Full Expected-checksum Cache

132.85 TFLOPS

将完整期望值移出 K-loop

Metadata kernel 为每条 checksum 分配一个 warp，32 个 lane 并行 K 维归约。主 kernel 只保留 actual reduction、阈值判断、纠正和写回。

阶段提升：3.34×First call：3.015 ms

for (int kk = lane; kk < k; kk += 32) {
  expected += avalue * b_sums[tile_col * k + kk];
}

for (int offset = 16; offset > 0; offset /= 2) {
  expected += __shfl_down_sync(0xffffffffU,
